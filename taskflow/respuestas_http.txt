================================================================================
REGISTRO DE CÓDIGOS DE ESTADO HTTP CON CURL - TASKFLOW API
(Resolución Tarea Clase 4 / Clase 4b)
================================================================================

CASO 200 OK
Comando: curl -i http://127.0.0.1:8000/api/tasks/2/
Primera línea: HTTP/1.1 200 OK
Cuerpo:
{"id":2,"project":1,"title":"Configurar CI","description":"","priority":"media","status":"pendiente","due_date":null,"tags":[],"created_at":"2026-09-21T19:04:32.716704Z","source":"proveedor_a"}
Observación: Respuesta exitosa al solicitar una tarea existente mediante GET.

--------------------------------------------------------------------------------

CASO 201 Created
Comando: curl -i -X POST http://127.0.0.1:8000/api/tasks/ -H "Content-Type: application/json" -d '{"project": 1, "title": "Nueva Tarea curl"}'
Primera línea: HTTP/1.1 201 Created
Cuerpo:
{"id":18,"project":1,"title":"Nueva Tarea curl","description":"","priority":"media","status":"pendiente","due_date":null,"tags":[],"created_at":"2026-09-30T18:20:12.541667Z","source":""}
Observación: Creación exitosa de un nuevo recurso mediante POST con campos requeridos válidos.

--------------------------------------------------------------------------------

CASO 204 No Content
Comando: curl -i -X DELETE http://127.0.0.1:8000/api/tasks/18/
Primera línea: HTTP/1.1 204 No Content
Cuerpo:
(vacío)
Observación: Eliminación exitosa de un recurso mediante DELETE. El servidor confirma la operación sin devolver contenido en el cuerpo.

--------------------------------------------------------------------------------

CASO 400 Bad Request
Comando: curl -i -X POST http://127.0.0.1:8000/api/tasks/ -H "Content-Type: application/json" -d '{"project": 1}'
Primera línea: HTTP/1.1 400 Bad Request
Cuerpo:
{"error":true,"detail":{"title":["This field is required."]}}
Observación: Error de validación por omisión del campo obligatorio 'title'. La respuesta viene envuelta por custom_exception_handler.

--------------------------------------------------------------------------------

CASO 404 Not Found
Comando: curl -i http://127.0.0.1:8000/api/tasks/999/
Primera línea: HTTP/1.1 404 Not Found
Cuerpo:
{"error":true,"detail":{"detail":"No Task matches the given query."}}
Observación: Recurso no encontrado. La respuesta 404 de DRF viene capturada y envuelta por custom_exception_handler.

--------------------------------------------------------------------------------

CASO 500 Internal Server Error
Comando: curl -i http://127.0.0.1:8000/api/tasks/romper/
Primera línea: HTTP/1.1 500 Internal Server Error
Cuerpo:
{"error":true,"detail":"Error interno del servidor."}
Observación: Forzado temporalmente con una acción @action romper (división por cero). Al ocurrir una excepción de Python no controlada por DRF, custom_exception_handler devuelve un 500 uniforme con el formato estándar de la API.

--------------------------------------------------------------------------------

- CASO 403 Forbidden: pendiente, Clase 7 (requerirá validación de permisos por rol o pertenencia).
